## ビジュアライゼーションの変遷（意図の記録）

初版は「6ステップを同じニューロン縦列で描く進捗バー」だった。ユーザーとのやり取りで、狙いが明確化するにつれ作り直した：

1. **進捗と同期させる** → タイマー駆動をやめ、`/api/chat` を NDJSON 化して実処理と連動。
2. **各ステップを固有の図解に** → 6本同じ絵ではなく、処理ごとに違う図。ニューロン演出は実際にNNを使う「ベクトル化」「応答生成」の2つだけ。
3. **左→右の流れ／操作可能カメラ** → カメラの向きが逆だったのを修正。ドラッグ・ピンチ・タップで操作。ステータスを図の中の HUD に統合、フォントを等幅の計器パネル調に。
4. **正確な再現＋3Dの奥行き活用** → 3Blue1Brown の図解から着想を得て図解の質を上げる。コサイン類似度は円錐、埋め込みは空間内の矢印、生成は「次トークン確率の棒→選択→末尾へ追加」で自己回帰を示す。カメラ既定は拡大で、ステップが進むと次モジュールへ寄る。

**核心の意図**：非力なGPU＋複数モデルのスワップで生成は遅い。その待ち時間を、単なるローディング演出ではなく「図を触って回して、仕組みを学べる時間」にする。それで体感待ち時間が短くなる。

### env で変えられること / コード固定値の場所

- env（`.env.local`）：モデル名、`OLLAMA_CHAT_NUM_CTX`、`OLLAMA_CHAT_THINK`、`CONVO_COMPRESS_TRIGGER_TOKENS`、`CONVO_KEEP_RECENT_TURNS`、`APP_PASSWORD`。変更後は `npm run build` → `npm start`
- コード固定値：RAG の `TOP_K=3` / `MAX_DISTANCE=0.75`（`src/lib/knowledge.ts`）、履歴上限 `MAX_MESSAGES_IN_PROMPT=24` / 事実抽出上限 `MAX_FACTS_PER_COMPACTION=5`（`src/lib/conversation.ts`）

### 次にやるなら（優先度順）

1. **`done` を圧縮より前に返す。** 現在 `src/app/api/chat/route.ts` は `generate → persist → compact → done` の順で、本文は `done` にしか乗らない。つまり圧縮が走る回は、要約モデルのロード（8GB VRAM では chat モデルの退避を伴う）が終わるまで画面に何も出ない。ユーザーの応答には不要な後片付けを待たせている。`await maybeCompact()` を `send({type:"done"})` の後ろへ動かすのが筋。ただし圧縮結果を同じ `done` に載せている（`compaction` フィールド）ので、通知の渡し方を先に決める必要がある
2. **応答のストリーミング表示。** 体感速度の次の改善。いまは生成完了まで本文が出ない
3. **長期知識の個別削除。** いまは全消去のみ
4. **正確なトークナイザ。** 圧縮の発火判定を文字数概算から実トークン数へ
5. **複数会話スレッド。** いまは1本のみ（仕様4.3・管理画面が「現在の会話」前提なので、そこも合わせて設計）
6. **同時送信のガード。** 会話マネージャーに簡単な mutex

### 変更の作法

設計方針を変えるときは、コードより先に `01_仕様書` → `02_調査結果` → `03_実行計画書` の順で更新する。実装が終わったら `README.md` と `/manual`（`src/app/manual/page.tsx`）も追従させる。

## 完了条件（全フェーズ達成済み）

- `ollama list` に3モデル、`npm start` でアプリ起動、`npx next build` パス（14ルート＋proxy）
- ブラウザ送信 → Ollama 応答が UI に表示、複数ターンで文脈保持
- 手動登録した知識が関連質問への回答に反映される
- 長い会話でも応答速度・安定性が大きく劣化しない（自動圧縮）
- 管理画面から状態確認・再起動・強制圧縮ができる
- 外出先スマホから管理画面含め一通り操作できる
- Ollama を意図的に停止させてもクラッシュせず適切なメッセージが出る
- メッセージ送信中、処理と同期したビジュアライゼーションが表示される
